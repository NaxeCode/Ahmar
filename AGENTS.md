## Work tracking: GitHub Issues and Projects

Track implementation in this repository's GitHub Issues, with a milestone and an
actionable issue that states what done means. Check existing issues and PRs before
creating another record. Use the private [NaxeCode portfolio](https://github.com/users/NaxeCode/projects/6)
for work across repositories, readiness and review. Repository issues and PRs own
current task state; the portfolio links to them.

Linear is retired. Do not create or update Linear tasks, request a Linear key, or
enforce older Linear-before-code instructions. Imported records need fresh scope,
ownership and acceptance checks before execution. Preserve historical references
and receipts. Keep private planning in a private Project draft until it is safe to
publish in this repository. If Issues is disabled on a fork, use that private draft
as the tracking record and identify the owning repository.

Every change goes through a pull request. Every PR requires Aladdin's personal
review of its current changes. Agents leave PRs unmerged: no self-approval,
auto-merge, direct integration-branch pushes or relaxed protections. Passing CI
or a machine review does not replace his review. Moving a task or saving a
recommendation does not authorize implementation. Follow any stricter repository
identity, branch and validation requirements.
